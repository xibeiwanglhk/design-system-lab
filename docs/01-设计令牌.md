# 01 · 设计令牌（Design Tokens）：一套值，驱动全站和 Figma

> 阶段 1 的目标：**看懂 `tokens/tokens.json`，会改、会加、会验证，并用它解释"为什么组件里不能写死色值"。**

---

## 1. 什么是设计令牌

设计令牌就是把"设计决策"变成有名字的变量：

```css
/* 不用令牌：色值散落各处，改一次要全局搜索替换，还容易漏 */
.button { background: #2563eb; }
.link   { color: #2563eb; }
.tag    { color: #2563eb; }

/* 用令牌：改一处，所有引用一起变 */
.button { background: var(--color-brand-bg); }
.link   { color: var(--color-brand-text); }
.tag    { color: var(--color-tag-text); }
```

同一个值在 **2 个以上地方**出现，就该抽成令牌；设计系统里通常还要跨 **Figma / Web / iOS / Android** 使用，所以令牌必须有一份**平台无关的真源**。本项目的真源就是 `tokens/tokens.json`。

---

## 2. 三层结构：core → semantic → dark

打开 `tokens/tokens.json`，顶层是三个"集合"（Tokens Studio 里叫 Token Set）：

```
core       原始值（Primitive）：蓝 600 是 #2563eb、间距 4 是 4px、圆角 md 是 10px
semantic   语义值（Semantic）：品牌背景 = 蓝 600、正文文字 = 灰 900、卡片内边距 = 20px
dark       主题覆盖（Theme）：暗色下，品牌背景 = 蓝 500、正文文字 = 灰 50……
```

为什么不直接只用一层？

| 层 | 回答的问题 | 改动频率 | 谁用 |
| --- | --- | --- | --- |
| `core` | "蓝 600 到底是哪个蓝？" | 很少（品牌色板调整） | 只被 semantic 引用 |
| `semantic` | "按钮背景该用什么？" | 中（设计决策） | **组件只能用这一层** |
| `dark` | "暗色下这个语义值换成什么？" | 中 | 编译时覆盖到同一个 CSS 变量 |

例子（`tokens.json` 节选）：

```json
{
  "core": {
    "color": { "blue": { "600": { "value": "#2563eb", "type": "color" } } },
    "space": { "5": { "value": 20, "type": "spacing" } }
  },
  "semantic": {
    "color": {
      "brand": {
        "bg": { "value": "{color.blue.600}", "type": "color" }
      }
    },
    "space": {
      "card-padding": { "value": "{space.5}", "type": "spacing" }
    }
  },
  "dark": {
    "color": {
      "brand": { "bg": { "value": "{color.blue.500}", "type": "color" } }
    }
  }
}
```

关键点：

- `"value": "{color.blue.600}"` 是**引用**，不是字符串字面量。编译器会解析它，最终得到 `#2563eb`。
- 引用可以省略 set 前缀（`{color.blue.600}` 会按 `core → semantic → dark` 顺序查找），也可以写全路径（`{core.color.blue.600}`）。
- token 的判定规则很简单：**对象里有 `value` 字段就是 token，否则就是分组**。

## 3. 命名规则：Figma 和 CSS 靠这一条规则对齐

编译器和 Figma 插件用的是**同一套规则**：

> **去掉最外层 set 名，剩下的路径用 `-` 连接并加 `--` 就是 CSS 变量名；用 `/` 连接就是 Figma 变量名。**

| tokens.json 路径 | CSS 变量 | Figma 变量 | 亮色值 | 暗色值 |
| --- | --- | --- | --- | --- |
| `semantic.color.bg.canvas` | `--color-bg-canvas` | `color/bg/canvas` | `#f8fafc` | `#020617` |
| `semantic.color.text.primary` | `--color-text-primary` | `color/text/primary` | `#0f172a` | `#f8fafc` |
| `semantic.color.brand.bg` | `--color-brand-bg` | `color/brand/bg` | `#2563eb` | `#3b82f6` |
| `semantic.radius.control` | `--radius-control` | `radius/control` | `10px` | 同左 |
| `semantic.space.card-padding` | `--space-card-padding` | `space/card-padding` | `20px` | 同左 |
| `semantic.font.size.body` | `--font-size-body` | `font/size/body` | `16px` | 同左 |
| `core.color.gray.500` | `--color-gray-500` | `color/gray/500` | `#64748b` | 同左 |

小提醒：

- 只有 `core` 里保留了 `gray/500`、`blue/600` 这类"色板名"；`semantic` 里不该再出现具体颜色名，只该出现用途名（`brand-bg`、`text-secondary`）。
- 同一个 CSS 变量名在 `:root` 和 `[data-theme="dark"]` 里可以有两份值（这是**故意覆盖**）；但同一个集合内部重名会编译报错。

## 4. 编译器做了什么：`scripts/build-tokens.mjs`

运行：

```powershell
node scripts/build-tokens.mjs            # 生成 src/styles/tokens.css
node scripts/build-tokens.mjs --check    # 只校验，文件过期则退出码 1（给 CI 用）
```

编译器流程（读源码顶部注释也能看到）：

1. **展平**：把三层嵌套的 JSON 展平成 `[set, path, token]` 列表。
2. **解析引用**：把 `{color.blue.600}` 递归解析成最终值；检测循环引用（`{a} → {b} → {a}`）。
3. **类型映射**：数字按类型补单位。

   | type | 输出 | 例 |
   | --- | --- | --- |
   | `color` | 原样 | `#2563eb` / `rgb(37 99 235 / 0.16)` |
   | `spacing` / `sizing` / `borderRadius` / `fontSizes` | 数字补 `px` | `20px` |
   | `duration` | 数字补 `ms` | `180ms` |
   | `lineHeights` / `fontWeights` / `number` | 原样（无单位） | `1.5` / `600` |
   | `fontFamilies` / `cubicBezier` / `boxShadow` | 原样 | `cubic-bezier(...)` |

4. **生成两个块**：`core + semantic` → `:root`；`dark` → `[data-theme="dark"]`。
5. **校验四件事**（这是它比"手写 CSS 变量"强的地方）：
   - 引用能否解析（拼错 token 名会报错）
   - 循环引用
   - CSS 变量重名
   - **组件里 `var(--xxx)` 用到的变量是否真的存在**（会扫描 `src/**/*.css` 和 `src/**/*.html`）

生成的 `tokens.css` 长这样（节选）：

```css
:root {
  /* ===== core ===== */
  --color-blue-600: #2563eb;
  /* ===== semantic ===== */
  --color-brand-bg: #2563eb;
  color-scheme: light;
}

[data-theme="dark"] {
  /* ===== dark ===== */
  --color-brand-bg: #3b82f6;
  color-scheme: dark;
}
```

> 生成文件头部会写"请勿手动修改"。改了下次编译会被覆盖，而且 CI 会判你不一致。

## 6. 动手练习 A：换一次品牌色（必须做）

目标：把品牌色从蓝换成紫，观察"只改原始值，语义值和组件一起变"。

**步骤**

1. 打开 `tokens/tokens.json`，找到 `core.color.blue.600`：

   ```json
   "600": { "value": "#2563eb", "type": "color" },
   ```

2. 改成紫色（同时把 400~800 也换掉，暗色的 hover、聚焦色和所有状态才会协调）：

   ```json
   "400": { "value": "#a78bfa", "type": "color" },
   "500": { "value": "#8b5cf6", "type": "color" },
   "600": { "value": "#7c3aed", "type": "color" },
   "700": { "value": "#6d28d9", "type": "color" },
   "800": { "value": "#5b21b6", "type": "color" },
   ```

3. 重新编译并刷新页面：

   ```powershell
   npm run tokens
   # 浏览器打开 http://localhost:4173/ 并硬刷新 Ctrl + F5
   ```

**验收**

- [ ] 主按钮、筛选选中态、链接颜色、标签底色、`--color-border-focus` 全部变紫
- [ ] 切换暗色，紫色依然协调（因为暗色覆盖的也是这批色板）
- [ ] `git diff` 里只有 `tokens.json` 和自动生成的 `tokens.css` 变化，**组件 CSS 一行没改**

> 改完记得改回来（或保留紫色作为你自己的主题，但要提交）。

## 7. 动手练习 B：新增一个令牌并用到组件上（必须做）

任务：给卡片媒体区一个更大的圆角 `--radius-media = 24px`。

**步骤**

1. 在 `tokens.json` 的 `semantic.radius` 里加一行（`core.radius.xl` 已经是 24）：

   ```json
   "media": { "value": "{radius.xl}", "type": "borderRadius" }
   ```

2. 重新编译：

   ```powershell
   npm run tokens
   ```

3. 在 `src/styles/components.css` 的 `.card__media` 里把 `border-radius: var(--radius-tag);` 改成：

   ```css
   border-radius: var(--radius-media);
   ```

4. 刷新页面 / 状态矩阵页看效果。

**验收**

- [ ] 编译输出里能看到 `--radius-media: 24px;`
- [ ] 卡片媒体区圆角明显变大
- [ ] 如果把组件里写成 `var(--radius-mediaaa)`（故意拼错），`npm run tokens` 会直接报错：

  ```
  ❌ 令牌编译失败：
     - 组件使用了未定义的 token 变量 --radius-mediaaa（出现在 src/styles/components.css）
  ```

**这一步的意义**：令牌不是"写给别人看的文档"，而是**有编译期校验的契约**。拼错变量名在 CI 就会失败，不会等到线上才发现。

## 8. 明暗主题是怎么实现的

只有两件事：

1. 令牌编译器把 `dark` 集合输出到 `[data-theme="dark"]`。
2. 页面在 `<html>` 上切换 `data-theme` 属性：

```js
document.documentElement.dataset.theme = 'dark';  // 走暗色令牌
delete document.documentElement.dataset.theme;    // 回到 :root 亮色令牌
```

CSS 变量是"继承 + 就近覆盖"的：`[data-theme="dark"]` 里的 `--color-bg-canvas` 会覆盖 `:root` 的同名变量，而组件 CSS 完全不用感知主题。

`app.js` 还做了三件小事：记住用户选择（`localStorage`）、防闪烁（在 `<head>` 里、样式表之前恢复主题）、支持 `?theme=dark` 强制主题（截图和导入 Figma 用）。

**练习**：在 `tokens.json` 的 `dark` 里给 `color.brand.bg` 换成另一个颜色（比如绿色 `#059669`），重新编译，打开 `states.html` 切暗色，看按钮和选中态是否只在暗色下变化。

## 9. 常见坑

| 坑 | 现象 | 正确做法 |
| --- | --- | --- |
| 直接改 `tokens.css` | 下次编译被覆盖，CI `--check` 失败 | 永远改 `tokens.json`，再 `npm run tokens` |
| token 名字里带颜色含义 | `--color-blue-bg` 在换品牌色后语义错乱 | 语义层用用途命名：`--color-brand-bg` |
| 组件里用 core 令牌 | 换主题时组件不跟随 | 组件只用 semantic（页面布局可用 core 的 `--space-8` 之类） |
| 图省事把值写死 | 改 token 组件不变，设计系统失效 | 永远 `var(--...)` |
| 引用写成 CSS 变量 | `"value": "var(--color-blue-600)"` 解析不了 | 引用必须写 token 路径：`"{color.blue.600}"` |
| 两层 token 同名 | 编译报 `CSS 变量重名` | 语义层换一个用途名，或在同一层只保留一个 |
| 忘了提交 `tokens.css` | 别人 clone 下来直接打开页面会没样式 | `tokens.css` 是生成物但**需要提交**；CI 会帮你保持同步 |
