# 06 · 排错速查与进阶路线

> 这个文件是"卡住时先看这里"的索引：**症状 → 原因 → 解决**。最后是进阶方向和自测题。

## 1. 排错速查表

### 1.1 环境与命令

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| `node : 无法将"node"项识别为……` | Node 没装 / 装完没重开终端 / PATH 没配 | 重装 Node LTS，关掉所有终端重开，`node --version` 验证 |
| `npm run dev` 报 `Missing script` | 不在项目根目录（找不到 `package.json`） | `cd` 到 `design-system-lab` 再运行 |
| 端口被占用 `EADDRINUSE` | 上一次的服务器没关 / 其他程序占用 4173 | 关掉旧进程，或 `node scripts/serve.mjs --port 4174` |
| 打开 `index.html` 双击是白屏 | 用了 `file://` 打开，部分浏览器限制模块/存储 | 用 `npm run dev` 起 http 服务器访问 |
| 终端中文乱码 | Windows 控制台编码不是 UTF-8 | 一般不影响文件；需要时 `chcp 65001` 或换 Windows Terminal |

### 1.2 令牌编译（`node scripts/build-tokens.mjs`）

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `组件使用了未定义的 token 变量 --xxx` | 组件 CSS/HTML 里拼错了变量名，或忘了在 tokens.json 定义 | 对照 `tokens.css` 里的变量名改正拼写，或补 token |
| `CSS 变量重名：--xxx` | 两个 set 里的 token 路径去掉 set 名后相同 | 给语义层 token 换个用途名；或在同一个 set 内只留一个 |
| `找不到引用目标 {color.xxx}` | `{引用}` 拼错 / 引用了不存在的 token | 在 tokens.json 里核对路径，注意省略 set 名的引用会按 core→semantic→dark 查找 |
| `检测到循环引用` | A 引用 B，B 又引用 A | 打破循环，让引用只指向"更原始"的一层 |
| `暗色 token … 在基础集中没有同路径 token` | 只在 `dark` 里定义了新 token，`semantic` 里没有 | 暗色只能覆盖已存在的 token；先在 semantic 定义默认值 |
| `tokens.css 已过期，请运行 npm run tokens`（`--check`） | 改了 tokens.json 但没重新生成 | 运行 `npm run tokens`，把 tokens.json 和 tokens.css 一起提交 |
| 生成后页面没变化 | 浏览器缓存 / 服务器没刷新 | `Ctrl + F5` 硬刷新；确认终端里 build 成功 |

### 1.3 样式与状态

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| 页面样式全部丢失 | CSS 路径错 / 文件名大小写错（Linux 区分大小写） | F12 → Network 看 3 个 CSS 是否 200；GitHub Pages 上核对大小写 |
| 按钮是浏览器默认样式 | `base.css`/`components.css` 没加载 | 看 Network；确认 `<link>` 顺序 tokens → base → components |
| 禁用按钮 hover 还变色 | disabled 规则写在 hover 前面，或被更高优先级覆盖 | 把禁用规则放在文件最后；hover 选择器加 `:not(:disabled)` 守卫 |
| 强制状态类没效果 | 类名拼错（是 `.is-hover`，不是 `.hover`） | 检查 class 名；确认规则写在组件 CSS 里 |
| 焦点环用鼠标点也出现 | 误用了 `:focus` | 改成 `:focus-visible` |
| 焦点环被裁切 | 父容器 `overflow: hidden` | 焦点元素外层不要裁切，或用 `outline-offset` 调整 |
| 手机上 hover 样式"粘住" | 触摸屏也会匹配 `:hover` | 把 hover 规则包在 `@media (hover: hover) and (pointer: fine)` 里（已实现） |
| 暗色切换瞬间白屏 | 主题在样式加载后才恢复 | 在 `<head>` 里、`<link>` 之前恢复 `data-theme`（已实现） |
| 动画卡顿/用户眩晕 | 没有尊重 `prefers-reduced-motion` | `base.css` 已全局降级；自定义动画也要遵守 |
| 卡片禁用后仍能点开 | 只有 CSS，没有 JS 拦截 `aria-disabled` | 在事件处理里判断 `card.getAttribute('aria-disabled') === 'true'`（参考 `app.js`） |

### 1.4 Git 与 GitHub

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| `fatal: not a git repository` | 当前目录不是仓库根目录 | `cd` 到 `design-system-lab`；`git rev-parse --show-toplevel` 检查 |
| `Authentication failed` / `403` | HTTPS 密码已废弃，要用 PAT | 用 Personal Access Token 当密码，或配置 SSH key |
| `rejected … non-fast-forward` | 远端有你本地没有的提交 | `git pull --rebase origin main` 后重推（先 commit 本地改动） |
| 默认分支是 `master` 但文档写 `main` | 仓库初始化时分支名不同 | `git branch -M main`；或把命令里的 main 换成 master |
| 推送后 Actions 没触发 | 路径过滤不匹配 / Actions 被禁用 | 看 workflow `on.push.paths`；Settings → Actions 确认允许 |
| `build-tokens` 提交失败（403） | 工作流权限不足 | Settings → Actions → General → Workflow permissions 选 **Read and write permissions** |
| Pages 404 | Source 没选 GitHub Actions / 部署还没跑完 | Settings → Pages → Source 选 **GitHub Actions**；等 Actions 的 deploy 步骤完成 |
| Pages 部署成功但资源 404 | HTML 里用了绝对路径 `/styles/...` | 改相对路径 `./styles/...` |
| 每次 CI 都产生巨大 diff | Windows CRLF 与 Linux LF 混用 | 已有 `.gitattributes`（`* text=auto eol=lf`），别删；`git add --renormalize .` 重跑一次 |
| 想撤销已推送的提交 | 直接 `reset --hard` 会破坏历史 | 用 `git revert <commit>` 生成反向提交 |

### 1.5 Figma 插件与同步

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| Plugins → Development 里没有 Import | 用的是浏览器版 Figma | 本地开发插件必须用 **Figma 桌面版** |
| 导入 manifest 报错 | manifest 路径/字段不对 | 选 `figma/plugin/manifest.json`；确认 JSON 无尾逗号 |
| 运行插件后变量没生成 | 粘贴的不是合法 JSON / 集合重名 | 先 JSON 校验；删除旧的 `Design Tokens` 集合再跑 |
| 没有 Dark 模式 | 免费 Starter 套餐不支持变量多模式 | 属预期行为，单模式 Light 可用；付费套餐（Professional+）支持多模式 |
| 免费版导出后暗色主题失效 | 单模式导出的 `dark` 是空对象，整文件覆盖会丢暗色令牌 | 插件日志若写"已自动恢复 dark 段"则可放心覆盖；否则按 [04 文档 2.18](./04-Figma同步.md#218-免费版怎么安全回写重要) 只合并改动值或补回 dark；`npm run tokens` 也会打印 `⚠️ dark 集合为空` 提醒 |
| 第二次运行插件后出现两套 Button/FeedCard | 变量会复用更新，但组件集不会自动复用 | 先把上一次生成的组件集删掉再运行；这是插件的已知限制（见 `figma/README.md`） |
| 组件文字是豆腐块 | 字体缺失，特别是中文字体 | 插件用系统可用字体；手动把字体改成 PingFang SC / Microsoft YaHei |
| 导出 JSON 后编译失败 | 导出的类型/引用与编译规则不一致 | 按 04 文档"导出后检查 3 项"逐条修（类型、引用路径、多模式） |
| Figma 改的东西代码没变 | 只改了画布，没改变量；或忘了导出/提交 | 只有**变量**能自动回到代码；画布结构改动需要人工写 CSS |

## 2. 进阶方向

按"投入产出比"排序，前三个最推荐。

### 2.1 给组件加行为（loading / toast / 表单校验）

- 组件库现在只有"外观状态"，下一步是"行为状态"。
- 练习：按钮 loading（`aria-busy`、spinner、防重复提交）、卡片骨架屏、空状态。
- 关键原则：**CSS 负责状态外观，JS 负责状态切换**，不要用 JS 直接改 style。

### 2.2 视觉回归测试（Playwright）

- 用途：改了 token 或组件 CSS 后，自动截图对比，防止"改 A 坏 B"。
- 思路：用 Playwright 打开 `states.html`，对每个状态格截图，与基线图 diff。
- 可以只写一个最小脚本，跑在 GitHub Actions 里，失败时上传 diff 图。

```js
// 伪代码：对状态矩阵逐格截图
import { test, expect } from '@playwright/test';
test('button states', async ({ page }) => {
  await page.goto('http://localhost:4173/states.html');
  await expect(page.locator('#button-states')).toHaveScreenshot('button-states.png');
});
```

### 2.3 Storybook（或纯 HTML stories）

- Storybook 适合组件多、多人协作；本项目这种零依赖练习可以先做"纯 HTML stories"。
- 好处：每个 story 固定一个状态，天然适合视觉回归和文档。
- 注意：Storybook 需要引入构建工具，会打破"零依赖"，建议放到独立分支/仓库玩。

### 2.4 Style Dictionary：一份令牌编译到多端

- 现在只编译 CSS；Style Dictionary 可以同时输出 SCSS、JS、iOS、Android、Flutter。
- 思路：把 `tokens.json` 作为输入，写 platform 配置，替换掉 `build-tokens.mjs` 里手写的转换逻辑。

### 2.5 CI 增强

在 `.github/workflows/` 里可以加：

```yaml
- name: 校验令牌
  run: node scripts/build-tokens.mjs --check
- name: 校验 HTML（示例）
  run: npx --yes html-validate "src/**/*.html"
```

还可以用 `actionlint` 检查 workflow 语法，避免"推送后才发现 YAML 写错"。

### 2.6 Code Connect：让 Figma Dev Mode 显示真实代码

- 条件：Figma Professional 及以上套餐 + Dev/Full 席位（以官方文档为准）。
- 价值：设计师/开发在 Figma 里选中 Button 组件，Dev Mode 直接显示 `components.css` 里的真实类名和 HTML 片段，而不是 Figma 自动生成的假代码。
- 做法：在仓库里放 `*.figma.ts` 模板文件，用 `figma connect publish` 发布。
- 对免费版的替代方案：在 Figma 组件描述里写"代码映射"（类名 + 文件路径），保持人工同步。

### 2.7 把组件发布成 npm 包

- 结构：`package.json` 里 `exports` 暴露 `./styles/tokens.css`、`./styles/components.css`。
- 构建：可以用 tsup/rollup 打成单文件，也可以直接发原始 CSS（本项目这种零依赖写法完全可以直接发）。
- 版本：遵循第 05 文档的语义化版本 + CHANGELOG。

### 2.8 发布 Figma 组件库

- 把变量集合和组件集所在文件在 Figma 里发布为 Library（需要付费套餐的 Library 能力）。
- 版本管理：Figma 的 Library 更新 + 你的 tokens.json 版本号要对齐（例如 `v1.2.0` 对应同一个 commit）。

### 2.9 设计系统治理（团队）

- token 提案流程：Issue 模板（要加什么 token、用在哪、亮暗两色值、对比度）。
- 变更评审：令牌改动必须同时更新 `tokens.json`、CSS 生成物、Figma、CHANGELOG。
- 可访问性门禁：对比度检查进 CI（可以用 `axe-core` 或人工检查清单）。

## 4. 30 分钟自测（答案在最后）

1. `semantic.color.brand.bg` 对应的 CSS 变量名和 Figma 变量名分别是什么？
2. 为什么组件里不允许写 `#2563eb`？
3. `core`、`semantic`、`dark` 各自解决什么问题？
4. 按钮四种状态在 CSS 里分别由哪些选择器/类名控制？
5. 为什么禁用态规则必须写在最后？
6. `:disabled` 和 `[aria-disabled="true"]` 的三个区别？
7. 数据流：在 Figma 里把品牌色改成紫色，要经过哪些步骤才能让线上页面变紫？
8. 为什么 `tokens.css` 是生成物却要提交到仓库？
9. `npm run tokens:check` 在 CI 里解决什么问题？
10. 这套方案里，哪些改动**不会**自动从 Figma 同步到代码？

<details>
<summary>答案（先自己想）</summary>

1. `--color-brand-bg` 与 `color/brand/bg`。
2. 写死值无法被令牌驱动：换品牌色/暗色主题时不会跟随，也绕过了编译期校验。
3. `core` 存原始值（色板/间距/圆角），`semantic` 存用途（按钮背景、正文颜色），`dark` 只覆盖暗色下需要变化的语义 token。
4. 默认 `.btn` + 变体类；hover 用 `:hover` 或 `.is-hover`；pressed 用 `:active` 或 `.is-pressed`；disabled 用 `:disabled`、`[aria-disabled="true"]` 或 `.is-disabled`。
5. 同优先级后写的生效；强制状态类与禁用选择器平级，禁用放最后才能保证任何情况下都是禁用外观。
6. 可否聚焦；是否触发 click（aria 版会触发，需要 JS 拦截）；读屏表现与适用场景（原生禁用 vs 逻辑禁用但需被感知）。
7. 改 Figma 变量 → 用插件导出变量 JSON → 覆盖 `tokens/tokens.json` → 本地 `npm run tokens` 或直接 push 让 Actions 重建 → 提交/推送 → Pages 部署 → 刷新页面。
8. 直接 clone 后无需 Node 也能打开页面；同时 CI 用 `--check` 校验生成物与源文件一致，避免"忘了重新生成"。
9. 防止有人改了 `tokens.json` 却没重新生成 `tokens.css`（生成物过期），PR 阶段就失败。
10. 组件的布局/结构/交互逻辑改动、Figma 画布上的手动修改（没沉淀成变量）、图片/字体资源等。

</details>

## 5. 下一步项目建议

1. **把信息流页做成你的个人主页**：替换文案和头像，保留组件库，部署到 Pages 当作品集。
2. **做一个"组件文档站"**：用 `states.html` 当起点，每个组件加使用说明、props 表、do/don't 示例。
3. **接一个真实小项目**：待办清单 / 博客列表 / 后台表格，全程只用 `btn` + `card` + 令牌，逼自己不加新样式。
4. **写一篇复盘**：记录"为什么选择 tokens.json 作为真源""Figma 到代码哪些能自动化"，这是面试/作品集里很值钱的内容。
